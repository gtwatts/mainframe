## Architecture

### 1. Metadata Pipeline

**Source**: `/home/gordontwatts/Documents/Projects/mainframe/FUNCTIONS.json`
- Generated by MAINFRAME's metadata extraction system
- Contains 4,000+ functions across 117 libraries
- Structure: `libraries -> functions -> params/signature/description`

**Transform**: `scripts/generate-lsp-metadata.sh`
- Uses `jq` for JSON transformation
- Flattens nested structure into flat completion array
- Builds signature index for functions with parameters
- Creates category and library indexes

**Output**: `~/.mainframe/FUNCTIONS.lsp.json`
- Optimized for LSP lookup performance
- ~2.5 MB file size
- Three main sections: completions, signatures, libraries

### 2. LSP Server Components

#### Connection Layer
```typescript
const connection = createConnection(ProposedFeatures.all);
const documents = new TextDocuments(TextDocument);
```
- Uses Node.js IPC or stdio for communication
- Manages document lifecycle (open, change, close)

#### Data Structures
```typescript
let metadata: LSPMetadata | null = null;
const functionLookup = new Map<string, CompletionItemData>();
const signatureLookup = new Map<string, FunctionSignature>();
```
- In-memory hash maps for O(1) function lookup
- Loaded once at server initialization
- ~15 MB memory footprint

#### Utility Functions

**getWordAtPosition**: Extract word under cursor
- Character-by-character boundary detection
- Matches regex: `/[a-zA-Z0-9_]/`

**findFunctionCalls**: Parse document for MAINFRAME functions
- Regex: `/\b([a-z_][a-z0-9_]*)\s*(?:\(|$|\s)/gi`
- Returns array of `{name, range}` objects

**getCurrentFunctionCall**: Detect active function for signature help
- Searches backward up to 200 characters
- Matches pattern: `/\b([a-z_][a-z0-9_]*)\s+[^;\n]*$/`

**buildHoverMarkdown**: Generate rich markdown documentation
- Structured sections: signature, description, parameters, examples, related
- Uses markdown code blocks for syntax highlighting

### 3. LSP Handlers

#### onInitialize
**Purpose**: Server startup and capability negotiation

**Capabilities Registered**:
- `textDocumentSync: Incremental`
- `completionProvider` with triggers: `['_', '$']`
- `hoverProvider: true`
- `signatureHelpProvider` with triggers: `[' ', '"', "'"]`
- `documentSymbolProvider: true`
- `definitionProvider: true`

#### onCompletion
**Purpose**: Smart autocompletion with snippets

**Logic**:
1. Check metadata loaded
2. Get document and current word
3. Map all completions to CompletionItem format
4. Build snippet if function has parameters
5. Apply category-based sorting

**Snippet Generation**:
```typescript
const placeholders = data.params
  .map((p, idx) => `\${${idx + 1}:${p.label}}`)
  .join(' ');
insertText = `${item.label} ${placeholders}`;
```

**Example Output**:
```bash
validate_int "${1:value}" "${2:min}" "${3:max}"
```

#### onHover
**Purpose**: Rich documentation on hover

**Logic**:
1. Get word at cursor position
2. Lookup in `functionLookup` map
3. Build markdown with `buildHoverMarkdown()`
4. Return as `Hover` with `MarkupKind.Markdown`

**Markdown Structure**:
```markdown
# function_name

```bash
signature
```

Description text

## Parameters
- **param1** required (default: `null`)
  Documentation for param1

**Returns:** `exit_code`

## Examples
```bash
example code
```

**Related:** func1, func2

*pure · idempotent*

---
*Library: strings · Category: utilities*
```

#### onSignatureHelp
**Purpose**: Parameter info as user types

**Logic**:
1. Find current function call context
2. Lookup in `signatureLookup` map
3. Build `ParameterInformation` array
4. Calculate active parameter by counting spaces

**Active Parameter Heuristic**:
```typescript
const afterFunc = lineText.slice(lineText.indexOf(funcName) + funcName.length);
const spaceCount = (afterFunc.match(/\s+\S+/g) || []).length;
activeParameter = Math.min(spaceCount, parameters.length - 1);
```

#### onDocumentSymbol
**Purpose**: Function call outline

**Logic**:
1. Find all MAINFRAME function calls in document
2. Build `DocumentSymbol` for each
3. Set `SymbolKind.Function`
4. Return array of symbols

**Use Case**: VSCode breadcrumb navigation, outline view

#### onDefinition
**Purpose**: Jump to library source

**Logic**:
1. Get word at cursor
2. Lookup in `functionLookup` map
3. Build file path: `$MAINFRAME_ROOT/lib/<library>.sh`
4. Return `Location` with `file://` URI

**Current Limitation**: Points to top of file (line 0)
**Enhancement Needed**: Parse library file to find exact function line

## Metadata Schema

### Completions Array

```typescript
interface CompletionItemData {
  label: string;              // Function name: "json_object"
  kind: string;               // "Function"
  detail: string;             // Full signature
  documentation: string;      // Description + metadata
  insertText: string;         // Plain name or snippet
  insertTextFormat: number;   // 1=PlainText, 2=Snippet
  sortText: string;           // "0-category-funcname"
  filterText: string;         // Lowercase search string
  tags: string[];             // ["category", "pure", "idempotent"]
  data: FunctionData;         // Rich metadata
}
```

### Signatures Array

```typescript
interface FunctionSignature {
  function: string;           // Function name
  signature: string;          // Full signature
  description: string;        // Description
  parameters: [
    {
      label: string;          // Parameter name
      documentation: string;  // Parameter description
      position: number;       // Positional index
      required: boolean;      // true/false
      default: string | null; // Default value
    }
  ]
}
```

### Libraries Array

```typescript
interface LibraryInfo {
  name: string;         // Library key: "json"
  file: string;         // Path: "lib/json.sh"
  description: string;  // Library description
  category: string;     // Category: "data"
  functionCount: number;// Number of functions
}
```

## Performance Optimization

### Metadata Loading
- **One-time**: Loaded at server initialization
- **Lazy**: Not loaded per-request
- **Cached**: In-memory hash maps for O(1) lookup

### Completion Latency
- **Target**: <10ms response time
- **Achieved**: ~5ms average (in-memory lookup)
- **No Network**: All data local

### Memory Footprint
- **Metadata**: ~2.5 MB JSON
- **Lookup Maps**: ~12 MB (two hash maps)
- **Total**: ~15 MB

### Scalability
- **Current**: 4,000+ functions
- **Projected**: 5,000+ functions
- **Impact**: Linear growth in memory, constant lookup time

## Error Handling

### Metadata Not Found
```typescript
if (fs.existsSync(metadataPath)) {
  // Load metadata
} else {
  connection.console.warn(`FUNCTIONS.lsp.json not found at ${metadataPath}`);
  connection.console.warn('Run: ./lsp/scripts/generate-lsp-metadata.sh');
}
```

### Parse Errors
```typescript
try {
  metadata = JSON.parse(data);
} catch (error) {
  connection.console.error(`Failed to load metadata: ${error}`);
}
```

### Missing Documents
```typescript
const document = documents.get(params.textDocument.uri);
if (!document) return null;  // Graceful degradation
```

## Known Issues

1. **Go-to-definition**: Currently jumps to top of library file, not exact function line
2. **Signature help**: Simple space-counting heuristic for active parameter (doesn't handle quotes/escapes)
3. **Function call detection**: Regex may miss complex bash syntax (command substitution, pipes)
